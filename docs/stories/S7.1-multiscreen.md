# S7.1 — мультимонитор зоны карточек + починка гонки Э1 (Э4-остаток)

Статус: **done** (15.09 — cardScreen cursor/primary/active; побочно поймана
и починена гонка холодного старта Э1 «карточка + нативный баннер»; живой
прогон владельцем на одном экране).

## Что/зачем

Зона карточек была жёстко от primary WorkArea — на двух мониторах карточки
уезжают на главный, даже когда юзер на втором. Решение владельца: настройка.
`cardScreen`: `"cursor"` (где мышь — дефолт, как нативные тосты) |
`"primary"` | `"active"` (переднее окно); null = cursor; читается на старте.
Владелец проверить два экрана не может (нет второго) — честная рамка:
один экран обязан вести себя идентично (проверено),跨-экранная геометрия —
код-ревью + пометка.

## Результат

- `Render/ScreenPicker` — WorkArea выбранного экрана в DIP:
  MonitorFromPoint/MonitorFromWindow (NEAREST) → GetMonitorInfoW (rcWork,
  физпиксели) → GetDpiForMonitor (effective) → DIP для WPF. Нет монитора/
  shcore — фолбэк primary. Смешанный DPI на стыках — микро-сдвиг, принять.
- Потребители переведены на пикер: `CardWindow.PlaceAtToastZone`,
  `CardStack.AnimateTo`, `CatchUpBanner` (OnLoaded + MoveAbove).
- `AppSettings.CardScreen` (round-trip тестом).
- MainWindow.LoadSettings ставит `ScreenPicker.Mode` + показывает в строке
  настроек `screen=…`.

## ГОНКА Э1 (побочная находка, важнее самой стори)

Живой прогон трёхрежимным циклом (3 рестарта с краш-маркером подряд) вскрыл:
**нативные баннеры поверх наших карточек**. Ход разбора: реестр в момент
проверки чист (global=0, 38/38) → «клин шелла» (§10a наоборот?) — опровергнут
спокойными пробами (без рестартов нативных нет). Истина: **холодный старт**
после деплоя долгий; фид начинает слушать ДО применения формулы; Apply
(версии S6.4) сначала ЧИНИЛ маркер (global=1 — баннеры включались на сотни
мс: снапшот 38 ключей + маркер на диск + 39 записей) и только потом гасил —
тост в зазоре давал карточку И баннер.

Лечение: на пути применения баннеры не включаются ВООБЩЕ — Apply
**принимает снапшот маркера как priors** (истинные «до нас»; новых после
краха отправителей читает из реестра), RepairedFromCrash ставится, маркер
переписывается свежим. Настоящий ремонт-восстановление остался только в
consent-ветке (TryRepairMarker). Живьем: холодная перестановка + тост —
только карточка.

## Живой прогон (пакет 0.1.0.0, один экран, глаза владельца)

- Три режима по кругу (cursor/primary/active, рестарты между): карточки все
  три раза в правом-низу, поведение идентично прежнему; строка настроек
  отражает режим.
- До фикса: те же тосты — нативные баннеры поверх карточек (нашёл гонку).
- После фикса: холодная перестановка + краш-маркер + тост — нативных нет.

## Разбор

- Окно «фид слушает, формула не применена» существует и после фикса
  (микросекунды записи) — несопоставимо с прежними сотнями мс.
- Приор «нового после краха отправителя» читается из реестра — если он
  получил blanket-ноль в сессии краха, чистый выход сохранит ему 0
  (баннеры того отправителя останутся выключенными) — редкий след,
  документирован.
- Владелец без второго монитора:跨-экранная геометрия живьём не проверена;
  одно-экранный инвариант (все режимы = прежнее поведение) проверен.

→ `CardStack.AnimateTo` → `NativeBannerSuppressor.Apply` (принятие маркера).
