## Что/зачем

Перенос листенера из спайк-кода (Spike52Engine, удалён) в `rnotify.Core` как
продукт-код: consent с таймаутом → подписка на `NotificationChanged` →
базлайн-снапшот (backlog молча) → диффы по Id с событиями наружу. Решения
владельца на план-гейте: **контент сразу** (`GetTextElements`, контракт
22621), **backlog молча пропустить** (дисковый floor — отложить до рендера),
**Spike52Engine удалить целиком**.

Гипотеза стори (спайк-фёрст): `GetTextElements()` читает title/body и в
packaged-режиме — опыт старого rnotif был unpackaged, спайк S5.2 читал только
Id/AUMID. Живой прогон = эксперимент, результат — факт в канон §10c.

## Разбор (послесессионный тур)

**Карта изменений**:

- `src/rnotify.Core/Listener/` — 7 файлов (~330): ядро Э2.
- `tests/rnotify.Core.Tests/` — проект + `FakeNotificationSource`,
  `NotificationCollector`, `NotificationFeedTests` (10).
- `src/rnotify/MainWindow.xaml(.cs)` — композиция Э2 + кнопка
  «Скопировать всё» (строки панели → клипборд одной пачкой).
- `src/rnotify/App.xaml.cs` — `Spike52.Run()` убран; мьютекс остаётся.
- Удалены: `Spike52Engine.cs`, `Spike52.cs`, `RegistryRestoreItem.cs`
  (откат Э1 уезжает вместе со спайком — применение формулы это S1.2).
- `rnotify.slnx` — строка тест-проекта.

**Решения и почему**:

- **Контракт 22621 — по projection-докам, не по памяти**: элементы
  `GetTextElements()` — `IReadOnlyList<AdaptiveNotificationText>` (свойство
  `.Text`); время — `UserNotification.CreationTime` (RaisedTime в проекции
  нет); `AppInfo` листенера даёт ТОЛЬКО `AppUserModelId` — DisplayName не
  существует, поле AppName выпало из записи. Имя/иконку отправителя резолвить
  отдельно (будущая сторя) — источник: XML-доки
  `microsoft.windows.sdk.net.ref/10.0.22621.57`.
- **События после Release семафора**: хендлеры не тормозят следующий дифф и не
  рвут его исключением; Added строго перед Removed — стабильный порядок для
  UI. Мутация `_seenIds` только под семафором — отдельный lock не нужен.
- **Базлайн под подпиской**: диффы по событиям встают в очередь за семафором,
  изменения между consent и базлайном не теряются (консент → подписка →
  снапшот; обратный порядок из спайка не проверялся — не рискуем).
- **Пачки сигналов** (событие летит на каждый чих хранилища): каждый сигнал =
  полный дифф-снапшот за семафором — дубли схлопываются сравнением множеств,
  тест «Пачка_Changed» фиксирует 4 снапшота и один Added.
- **Грабли коллекционных выражений**: spread `[.. seq]` порождает синтетический
  тип `<>z__ReadOnlyList<>` в ГЛОБАЛЬНОМ namespace — arch-тест «типы ядра в
  пространстве ядра» падал; в Core вместо spread — `.ToArray()`/`.ToHashSet()`.
- **EventArgs: sealed-классы, не records** — MA0046 требует EventArgs-наследника,
  первичный конструктор record не умеет (CS8864).
- **Кнопка «Скопировать всё»** — канал верификации владельца (вместо
  скриншотов поверх чужих окон): строки панели дублируются списком, клик
  копирует пачку; занятый клипборд — `ExternalException` в подписи кнопки.

**Маршрут чтения**: `NotificationFeed.cs` (протокол старта/диффов) →
`ToastContentReader.cs` (контент 22621) → `UserNotificationSource.cs` (шов
над WinRT) → `MainWindow.xaml.cs` (композиция) → `NotificationFeedTests.cs`.

**Как проверить руками**: собрать подписанный пакет (README «Сборка») →
`Add-AppxPackage` → запуск: панель показывает Consent=`Allowed`, Baseline=N,
ни одного `+ id` при старте → `powershell -File spikes/tools/send-test-toast.ps1
-Title 'S2.1 title' -Body 'S2.1 body'` → строка `+ id … …powershell.exe ·
S2.1 title — S2.1 body` → «Скопировать всё» → вставка в сессию. Нативный
баннер может показаться — Э1 продукт ещё не применяет.

**Отложено сознательно**: floor на диске (анти-дубли между запусками — нечего
решать до рендера); наблюдение позднего consent-ответа (диагностика спайка);
CancellationToken (WinRT-методы не принимают); юнит-тест ToastContentReader
(WinRT-типы без публичного ctor — закрыл живой прогон); имя/иконка отправителя
(AppInfo без DisplayName — отдельная сторя).
