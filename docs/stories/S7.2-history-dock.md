# S7.2 — док-панель истории (Э4-остаток, канон §9 компонент 5)

Статус: **done** (15.09 — хоткей+меню, поиск, фильтр, повтор, копирование;
скрытие при потере фокуса; TTL повтора настройкой; живой прогон владельцем).

## Что/зачем

Канон §9: «Док: глобальный хоткей → панель истории, поиск, повторный
показ». Гейтовые решения владельца: хоткей Win+Shift+N **настройкой**
(`historyHotkey`, принцип «всё в настройки»); храним **всё с пометкой
действия**, панель по дефолту показывает только показанные (`historyOnlyShown`,
фильтр снимается в панели); действия повтор+копирование **расширяемым
реестром**; глубина `historyLimit` (дефолт 1000); TTL повторной карточки
`historyReshowTtl` (дефолт "3m", "sticky" = руками — после живого прогона
«висят бесконечно, надо настраивать»).

## Результат

- `rnotify.Core.History`: `HistoryEntry` (unix-время, AUMID, имя на момент
  записи, титул, тело, действие) + `HistoryStore` — history.json, атомарная
  запись на каждое уведомление (из пула, под локом), чистка до лимита
  (свежайшие), битый файл = пусто, лимит 0 = выключено. 4 юнит-теста.
- `src/rnotify/History/HistoryWindow.xaml(.cs)`: одна на приложение
  (ShowSingle); поиск по отправителю/титулу/телу, галка «только
  показанные» (дефолт — настройка), счётчик «N из K», обновление; двойной
  клик и кнопка ↺ — повтор карточкой (TTL из настройки), ⧉ — копирование
  полного текста; Esc — закрыть; **потеря фокуса — Hide** (хоткеем
  поднимается обратно). Действия — записи `HistoryAction(Glyph, Hint,
  Run)` в строке: расширяемый реестр.
- Хоткей: `TrayIcon.TryRegisterHotkey(spec)` — RegisterHotKey на окно
  трея, WM_HOTKEY в WndProc → событие; парсер "Win+Shift+N" (модификаторы
  Ctrl/Alt/Shift/Win + буква/цифра/F1–F12, мусор → false → путь меню).
  В packaged работает (живой прогон). Unregister в Dispose.
- `RulesEngine.ParseTtl` публичным (переиспользован настройкой).
- MainWindow: запись истории в общем пути ProcessNotification; строка
  состояния хоткея; OpenHistory/OnHistoryReshow (повтор — в стек напрямую,
  без вердикта и без дубликата в истории).

## Живой прогон (пакет 0.1.0.0, глаза владельца)

- Win+Shift+N и ПКМ-меню «История…» открывают; пропадает фокус — прячется.
- Список наполняется (проба + живой rhub); поиск фильтрует; фильтр
  «только показанные» снимается.
- Двойной клик — липкая карточка повторно; TTL 3m — «выждал 3 минуты,
  пропала».
- Кнопки копирования/повтора заработали после фикса (см. разбор).

## Разбор

- **DataContext ячейки vs строки**: кнопки-действия лежат в ItemsControl
  внутри колонки GridView — DataContext кнопки это САМО действие, а не
  RowViewModel строки; обработчик молчал (живой прогон: «кнопка которая
  ничего не делает», «копирование нет»). Лечение — подъем по визуальному
  дереву до ListViewItem. Дубль-клик работал — шёл через ListView.
- Повтор карточкой = CatchAll с TTL из настройки: правила НЕ
  перезапускаются (заглушенное повтором не гасится) и история не
  дублируется.
- БЭКЛОГ (идея владельца, живой прогон): при переполнении стека
  повторов старшая карточка исчезает бесследно; хочется «3 на экране +
  плашка "скрыть всё" сверху, старые подкладываются ПОД плашку и чуть
  торчат — видно, что их там несколько». Занесено в ROADMAP Э4-остаток.
- RegisterHotKey из packaged MSIX — без capability, работает (факт в канон
  не вынесен — тривиально, но отмечено здесь).

**Маршрут чтения**: `Core/History/HistoryStore.cs` → `History/
HistoryWindow.xaml.cs` (фильтр/действия/ShowSingle) → `Tray/TrayIcon.cs`
(TryRegisterHotkey/WM_HOTKEY) → `MainWindow` (запись + OnHistoryReshow).

**Как проверить руками**: тост → Win+Shift+N → поиск → дубль-клик →
карточка уходит по historyReshowTtl → ⧉ в буфер.

**Отложено сознательно**: подкладка-стек под плашку (бэклог); хоткей в
UI-редакторе настроек; поиск по дате; авто-обновление открытой панели
(сейчас кнопкой/переоткрытием).
