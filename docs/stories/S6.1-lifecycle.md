# S6.1 — жизненный цикл: трей + автозапуск (Э6)

Статус: **done** (14.09 — закрытие окна = свернуть в трей (демон жив, Э1
держится), выход из меню трея, автозапуск MSIX StartupTask с чекбоксом,
скрытый старт по автозапуску, повторный запуск разворачивает панель; живой
прогон владельцем).

## Что/зачем

До S6.1 жизнь приложения = окно-панель (ShutdownMode=OnMainWindowClose):
закрыл окно → процесс вышел → формула Э1 снялась. Для постоянного диспетчера
нужен режим демона: стартовать с системой, жить в трее, показывать панель по
запросу. Решения план-гейта: автозапуск — чекбокс в меню трея (settings.json
`autostart` + `StartupTask.RequestEnableAsync/Disable`); старт по автозапуску —
сразу в трей (окно скрыто), ручной — панель как обычно.

## Результат

- `src/rnotify/Tray/TrayIcon.cs` — Shell_NotifyIcon на чистом P/Invoke
  (нуль зависимостей): скрытое окно HwndSource + AddHook (callback в
  UI-потоке), Win32-меню (CreatePopupMenu/TrackPopupMenu c _tpmReturnCmd и
  танцем SetForegroundWindow+WM_NULL), левый клик → панель; пункты
  «Панель / Автозапуск (галочка) / Выход».
- `src/rnotify/Tray/AutostartManager.cs` — WinRT StartupTask (TaskId
  `rnotifyStartup`): RequestEnableAsync (система решает — юзер/политика)
  / Disable.
- Манифест: namespace uap5 + `windows.startupTask` (Enabled=false — включается
  чекбоксом, не навязанно при установке).
- `App`: ShutdownMode=OnExplicitShutdown, StartupUri убран (окно руками:
  автостарт стартует скрытым); второй инстанс сигналит EventWaitHandle
  `Local\rnotify-show-panel` — панель разворачивается, дубли нет; активация
  `StartupTask` детектится `AppInstance.GetCurrent().GetActivatedEventArgs()`
  (WASDK 2.4: instance-член).
- `MainWindow`: OnClosing — `!_exiting` → Cancel+Hide (Э1 НЕ снимается);
  настоящий выход («Выход» меню) доезжает до OnClosed → Restore последним →
  `Application.Current.Shutdown()`. Чекбокс трея: settings.json `autostart`
  (поле + `Save` в Core, атомарно) + StartupTask + строка состояния в панель.
- Иконка: `Assets/rnotify.ico` (BMP-кадры 16/24/32/48 из Square150,
  `spikes/tools/make-ico.ps1`) — **встроенный ресурс сборки** (pack URI),
  HICON — `CreateIconFromResourceEx` по ближайшему к SM_CXSMICON кадру.

## Живой прогон (пакет 0.1.0.0, Win 26200, глаза владельца + «Скопировать всё»)

- Старт: панель + фиолетовая иконка в трее; строки «Настройки … autostart=…»,
  «Э1 применена (38)», «Трей …».
- WM_CLOSE окна (аналог X): процесс жив, окно скрыто, Э1 держит (global=0,
  маркер на диске); тост в трей-режиме — наша карточка, нативного нет.
- Повторный запуск: процесс один, панель развернулась (сигнал).
- Меню трея: «Панель/Автозапуск/Выход»; чекбокс → «Автозапуск = включён
  (state: Enabled)» + settings.json `autostart:true` (пережил рестарт).
- «Выход»: процесс ушёл, реестр возвращён (global=1, 0/38 ShowBanner,
  маркер стёрт).

## Разбор

- **LoadImage по файлу в WindowsApps = ERROR_FILE_NOT_FOUND** при живом файле
  (читается из PS!). Лечение: иконка — Resource сборки, HICON из байтов
  `CreateIconFromResourceEx`. Урок: файловые пути user32-семейства в packaged —
  мина, ресурсы сборки — надёжно.
- **PNG-кадры .ico рендерятся пустотой**: первая итерация (PNG-фреймы, 888
  байт) дала слот без картинки; BMP-кадры (17.5 КБ) рисуются. `make-ico.ps1`
  пишет классический формат (BITMAPINFOHEADER c biHeight=2×, BGRA, AND-маска).
- **HwndSource создаёт окно ВИДИМЫМ** (0×0 за экраном): Get-Process считал его
  «главным окном» (панель «исчезала» из проб), торчало в z-порядке — гасим
  `ShowWindow(SW_HIDE)` сразу после создания. Побочно: пробы владельца из
  моего шелла (EnumWindows/FindWindow) не видят окна GUI-сессии вообще —
  истина только Get-Process + прямые хэндлы.
- **Окно трея глотает WM_CLOSE**: taskkill без /F бьёт по ВСЕМ top-level окнам
  процесса; HwndSource от WM_CLOSE уничтожается → иконка сиротеет. Перехват
  `handled=true`.
- **Скрытый старт = Show()+Hide() одним стек-фреймом**: Loaded обязан
  стрелять (инициализация в нём), рендера между вызовами нет — окна не видно.
  Проверено активацией Launch (титул-инструментация): ветка не срабатывает
  на ручном запуске.
- WASDK 2.4: `AppInstance.GetActivatedEventArgs()` — instance-член
  (`GetCurrent().`…), не статический, как в 1.x.
- Add-AppxPackage на ту же версию с другим содержимым = 0x80073CFB
  (повтор грабли S1.2): Remove + Add.
- Два GetActivatedEventArgs-вызова подряд давать нельзя диагностики ради —
  расходятся; один вызов, результат — в переменную.

**Маршрут чтения**: `Tray/TrayIcon.cs` (P/Invoke, меню, ресурс-иконка) →
`Tray/AutostartManager.cs` → `App.xaml.cs` (мьютекс → сигнал → окно → ветка
скрытого старта) → `MainWindow.xaml.cs` (OnClosing-в-трей, OnTrayAutostart,
разборка OnClosed) → `Package.appxmanifest` (uap5:startupTask).

**Как проверить руками**: README «Трей и автозапуск».

**Отложено сознательно**: скрытый старт по автозапуску глазами (нужна
перезагрузка/вход — механизмы Launch-ветки проверены, StartupTask-ветка
