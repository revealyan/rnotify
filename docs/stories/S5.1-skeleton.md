## Что/зачем

Каркас решения по решению «MSIX с первого дня»: packaged WPF-хост-заглушка +
ядро + строгость сборки + границы. Даёт хост для спайка S5.2 (registry-виртуализация
Э1, NotificationChanged с identity) и швы для Э2–Э4. Бизнес-кода нет (PoC rnotif —
источник гипотез, не кода).

Решения: UI-хост WPF (владелец; финальный стек — спайк Э4, поэтому хост тонкий);
packaging — single-project MSIX через Windows App SDK 2.4.0, self-contained
win-x64 (дев-установка без установленного runtime); identity — из
`docs/store-identity.md`.

- `dotnet build` зелёный (TWaE, анализаторы Roslynator/Meziantou/BannedApi).
- `dotnet format --verify-no-changes` чист; `dotnet test` зелёный (4 arch-правила).

## Разбор (послесессионный тур)

**Карта изменений** (все файлы новые):

- Рельсы: `global.json` (SDK-пин + `"test": {"runner": MTP}` — новый режим
  `dotnet test` на .NET 10), `Directory.Build.props` (кит строгости),
  `Directory.Packages.props` (CPM: ОБА флага — NU1015 на SDK 10.0.3xx),
  `.editorconfig`, `BannedSymbols.txt`, `.github/workflows/ci.yml`.
- Ядро `src/rnotify.Core`: `ProductIdentity` (Name/Publisher/MutexName),
  `Suppression/README.md` — шов посадки формулы Э1 (S1.2).
- Хост `src/rnotify`: `App` (single-instance mutex — продуктовый инвариант;
  комментарий-шов «S5.2: спайк сюда»), `MainWindow` (панель identity из
  `Package.Current.Id`, guard на unpackaged-F5), MSIX-пропсы в csproj,
  `Package.appxmanifest`, лого-плейсхолдеры.
- Тесты `tests/rnotify.ArchTests`: 4 правила границ.
- Инструменты: `tools/dev-cert.ps1` (ASCII: PS 5.1 + кириллица без BOM ломается,
  канон §10a).

**Решения и почему**:

- `ProductIdentity` — `static readonly`, НЕ `const`: константы инлайнятся в
  место использования, AssemblyRef на ядро исчезает из метаданных, и arch-тест
  «app ссылается на Core» ловит пустоту (поймано на практике).
- Подпись условная (`AppxPackageSigningEnabled` по `Exists(pfx)`): чистый клон и
  CI собирают unsigned-пакет и остаются зелёными; локально с сертификатом —
  подпись. Пароль от pfx в csproj — осознанно: pfx gitignored, машинный, не секрет.
- ArchTests правило B (app→Core) — рефлексией `GetReferencedAssemblies()`, не
  NetArchTest: тот видит только сигнатурные зависимости, а ядро пока
  используется в телах методов (ловушка проверена).
- `runFullTrust` в манифесте — обязательная restricted capability packaged
  desktop-приложения (MakeAppx отказал без неё).
- xunit.v3 + MTP: тест-проект `OutputType=Exe`; `dotnet test` требует
  `"test": {"runner": "Microsoft.Testing.Platform"}` в global.json.

**Маршрут чтения**: `Directory.Build.props` → `src/rnotify.Core/ProductIdentity.cs`
→ `src/rnotify/App.xaml.cs` (швы S5.2) → `src/rnotify/MainWindow.xaml.cs` →
`tests/rnotify.ArchTests/ArchitectureTests.cs` → `src/rnotify/rnotify.csproj`
(MSIX-механика) → `tools/dev-cert.ps1`.

**Как проверить руками** (admin-консоль): `tools/dev-cert.ps1` →
`dotnet build -c Release src/rnotify` → `Add-AppxPackage src\rnotify\AppPackages\rnotify_0.1.0.0_x64_Test\rnotify_0.1.0.0_x64.msix`
→ окно показывает `revealyan.RNotify`/Publisher/0.1.0.0, второй запуск молча
выходит → `Remove-AppxPackage`. *Выполнено 12.09*: сертификат доверен
(владелец), пакет установлен (`SignatureKind Developer`, Status Ok), текст окна
проверен UIA (Name/Version/Publisher/FamilyName верны, «Совпадение с
ProductIdentity: да»), повторный запуск оставил один процесс.

**Журнал подавлений**: CA1707 отключён в тест-проекте (snake_case-имена тестов);
APPX0105/APPX0107 заглушены в app-csproj (шум упаковщика при живой подписи pfx).

**Известный шум**: один warning `mspdbcmf.exe not found` от MSIX-таргета (symbols

Проверить на первом пуше: зелёность CI (actions versions), сроки.

**Отложено сознательно**: трей-иконка, VM/библиотеки UI (тонкий хост до Э4);
`rnotify.Core.Tests` (юнит-тесты родятся в Э2 с логикой); версионирование
манифеста из CI, релизный MSIX, стор-сабмит (S5.3); перенос Listener/Rules из
