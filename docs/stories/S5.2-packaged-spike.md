# S5.2 — спайк: packaged-режим (виртуализация Э1, NotificationChanged, consent)

Статус: **review** (12.09 — эксперименты проведены, факты в каноне §10c и
`spikes/SPIKE-S5.2.md`; ждёт прочтения владельцем).

## Что/зачем

Три вопроса, без которых продукт в packaged-режиме не строится: (Г1) доходят ли
ключи формулы Э1 из packaged-процесса до реального HKCU (или MSIX
virtualization прячет их от WpnService); (Г2) работает ли `NotificationChanged`
с identity (в unpackaged PoC падал `0x80070490` → поллинг); (Г3) как ведёт
себя consent `RequestAccessAsync` в пакете. Решение владельца по границам:
глобальный NOC-тумблер на живой машине не трогаем (per-app ключ механикой
записи тот же); спайк-код остаётся в app до Э2.

## Результаты (полный протокол — `spikes/SPIKE-S5.2.md`, канон §10c)

- **Г1**: виртуализация есть — записи уходят в `Helium\User.dat` пакета,
  реальный улей чист. Capability `unvirtualizedResources` одна НЕ лечит;
  лечит пара: capability **+** `desktop6:RegistryWriteVirtualization=disabled`
  в `Properties`. После этого ключи в реальном улье, эффект подтверждён парой
  опыт/контроль BMP-дифом (баннер 2108 против шума 99).
- **Г2**: `NotificationChanged` работает (событие < 1 с, диф по Id корректен),
  `0x80070490` не воспроизвёлся → Э2 на событиях, без поллинга.
- **Г3**: `Allowed` за ~80 мс без диалога.

## Разбор (послесессионный тур)

**Карта изменений**:

- `src/rnotify/Spike52Engine.cs` (новый, ~330) — движок трёх проб: Г1
  `ProbeKey` (прочитать прежнее → записать DWord → read-back; rollback-список),
  Г3 `RequestAccessWithTimeoutAsync` (WhenAny + поздний ответ continuation'ом),
  Г2 подписка + `DiffSnapshotAsync` (SemaphoreSlim-сериализация пачек, диф
  `HashSet<uint>` по Id). Роль: референс контракта 22621 до Э2.
- `src/rnotify/Spike52.cs` (новый) — static-фасад с guard от double-run.
- `src/rnotify/RegistryRestoreItem.cs` (новый) — record для точного отката.
- `src/rnotify/App.xaml.cs` — `Spike52.Run()` в OnStartup (шов S5.2 закрыт
  до переноса в Core в Э2).
- `src/rnotify/Package.appxmanifest` — пара
  `unvirtualizedResources` + `RegistryWriteVirtualization=disabled` (остаётся
  в продукте навсегда — это условие применимости формулы Э1).
- `spikes/tools/spike52-banner-check.ps1` (новый) — DPI-aware BMP-диф проверки
  баннера (по образцу `spike-e1e.ps1`, упрощён до пары опыт/контроль).
- `spikes/SPIKE-S5.2.md` (новый) — протокол: гипотезы → метод → 11 фактов.

**Решения и почему**:

- Лог — файл (UTF-8 с BOM: PS 5.1 ломает кириллицу без BOM, §10a) + панель;
  файл — истина по порядку строк, панель — удобство. Путь печатается первой
  строкой: у packaged `%LOCALAPPDATA%` редиректится в LocalCache, путь из
  `GetFolderPath` показывает «виртуальный» вид.
- Read-back внутри процесса помечен «merged view» — самопроверка Г1 не
  доказательство, истина только внешний `reg query` (поймано при проектировании).
- Откат Э1 на `Application.Exit` — по доктрине «при выходе вернуть прежние»;
  в раунде 1 откат виртуальный (безвреден), в 2b — реальный.
- Тестов на спайк-код нет осознанно: он одноразовый эксперимент, живёт до Э2;
  arch-тесты границ не затронуты.

**Маршрут чтения**: `spikes/SPIKE-S5.2.md` → `Spike52Engine.cs` (`RunAsync` —
порядок секций, `ProbeKey`, `DiffSnapshotAsync`) → `Package.appxmanifest`
(пара capability+property) → канон §10c.

**Как проверить руками**: установить пакет (README), окно печатает секции
Г1/Г3/Г2 в IdentityPanel; в отдельной консоли `reg query` per-app ключа
(`ShowBanner` должен быть виден снаружи); `spikes/tools/send-test-toast.ps1` →
в логе `NotificationChanged #N` и `+ id=…`; закрыть окно → ключи исчезли.

**Отложено сознательно**: blanket-применение формулы Э1 всем отправителям и
глобальный тумблер (S1.2); контент уведомлений через `Visual.Bindings` (Э2);
юнит-тесты `rnotify.Core.Tests` (Э2); обоснование restricted declarations для
стора (S5.3).

## Горизонт

- **Э2**: транспорт — события `NotificationChanged` (факт Г2), `Spike52Engine`
  переносится в `rnotify.Core/Listener/`, хов-комментарий в `App.OnStartup`
  заменится композицией.
- **S1.2 (подавление)**: механика записи готова — пара в манифесте уже
  обеспечивает доставку ключей; blanket per-app + глобальный тумблер с откатом
  поверх `ProbeKey`-паттерна.
- **S5.3 (стор)**: restricted declarations требуют обоснования в сабмишне —
  зафиксировано в §10b/§10c канона.
