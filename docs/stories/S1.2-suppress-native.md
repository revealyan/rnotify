# S1.2 — формула Э1 в продукте: подавление нативных баннеров (Э1)

Статус: **done** (14.09 — Apply после consent, blanket новых отправителей,
Restore на выходе, крах-безопасность маркером; живой прогон владельцем:
баннеры гаснут при работе и возвращаются после выхода, rhub только наш).

## Что/зачем

Э1-продукт: валидированная спайком 12.09 формула (канон §10) применяется
приложением — глобально `NOC_GLOBAL_SETTING_TOASTS_ENABLED=0` + blanket per-app
`ShowBanner=0` всем отправителям. До сих пор нативные баннеры были включены
параллельно нашим карточкам («наша карточка + нативный баннер» — дубли);
mute правилами тоже не был настоящим. После S1.2 показ — только наш рендер.

Решения владельца (план-гейт 14.09):
1. **Consent ≠ Allowed → настройка** `suppressWithoutListener`
   (`%USERPROFILE%\.rnotify\settings.json`, дефолт false): без согласия
   листенера карточек нет — молчаливое гашение оставило бы юзера вовсе без
   уведомлений; дефолт безопасен, поведение переключается файлом.
2. **Крах-безопасность — маркер-файл**: снапшот прежних значений пишется в
   `suppression.json` ДО записей формулы, стирается после успешного Restore;
   следующий старт видит маркер — чинит реестр и применяет заново.
3. **Возврат глобального**: prior был 0/1 → пишем его; не было → явная `=1`
   (§10a: удаление значения не будит внутреннее состояние шелла — баннеры
   остались бы мёртвыми; финал спайка Э1). Per-app: prior был → пишем, не
   было → настоящий `DeleteValue` (возврат баннера валидирован S5.2).

## Результат

- `src/rnotify.Core/Suppression/` (контракт из README-заглушки):
  - `INotificationSettingsRegistry` — шов над кустом HKCU
    `...\Notifications\Settings` (7 операций: перечисление отправителей,
    get/set/delete DWORD в корне и у отправителя); прод —
    `RegistryNotificationSettings` (Microsoft.Win32), тесты — in-memory фейк.
  - `NativeBannerSuppressor` — вся логика: `Apply()` (авторепейр по чужому
    маркеру → снимок priors → маркер на диск → глобальный 0 → blanket всем;
    сбой на полпути — откат написанного и исключение наружу),
    `BlanketSender(aumid)` (новый отправитель с фида; из пула, под локом,
    не бросает — трейс-строка), `Restore()` (priors по семантике гейта,
    стирание маркера), `Dispose` (страховочная сетка). Трейс — событие
    `Trace` (EventHandler) в панель.
  - `SuppressionSnapshot` — record priors (null = значения не былó); он же
    — содержимое маркера (json, атомарная запись tmp+Move как RulesStore).
- `src/rnotify.Core/Settings/` — `AppSettings`/`AppSettingsStore`:
  settings.json, одно поле `suppressWithoutListener`; файла нет — создаётся
  дефолт; битый json — дефолт на память, файл не трогается (булево поле,
  потерь юзера нет — мягче доктрины rules.json), ошибка наружу. Читается
  один раз на старте, хот-релоада нет (поле влияет только на consent-решение).
- Врезка `MainWindow`: `StartSuppression(start.Status)` после строк consent
  (Allowed → Apply; иначе — по настройке, дефолт «не гасим» + строка);
  `OnNotificationAdded` → `_suppressor.BlanketSender(e.Record.Aumid)` (пул);
  `OnClosed` → Restore ПОСЛЕ диспоза фида (баннеры возвращаются, когда фид
  уже молчит), затем Dispose-сетка.
- Тесты: 11 новых (41 всего) — apply/restore-priors/глобальный-ноль-юзера/
  краш-репейр-не-теряет-priors/идемпотентность/blanket (новый, пустой,
  повтор, до Apply)/сбой-посреди-записей-откатывает/settings (дефолт,
  чтение, битый).

## Живой прогон (пакет 0.1.0.0, Win 26200, глаза владельца + «Скопировать всё»)

- Старт: «Настройки = …suppressWithoutListener=False» (дефолт создан),
  «Э1 применена: глобальный тумблер 0 + ShowBanner=0 (38 отправителей)» —
  реестр: `NOC_GLOBAL=0`, маркер на диске, 38/38 подключей под `ShowBanner=0`.
- Тост-проба: **наша карточка есть, нативного баннера нет**; живой rhub-трафик
  — тоже только наш рендер («rhub уведомление тоже пришло только в нашем виде»).
- Blanket на лету: тост из powershell с AUMID-полным путём → строка
  «Э1: новый отправитель powershell.exe (ShowBanner=0)» (полный путь —
  отдельный подключ, не входил в стартовые 38).
- Краш (taskkill /F): маркер жив, реестр остался погашенным.
- Перезапуск: «маркер прошлой сессии — реестр отремонтирован перед
  применением» + свежее «Э1 применена (38)» — авторепейр работает.
- Штатный выход (WM_CLOSE): глобальный → `1` (явная запись), `ShowBanner=0`
  не осталось ни у одного из 38, маркер стёрт; контрольный тост и rhub —
  **нативные баннеры вернулись** (глаза владельца; логика: процесс мёртв,
  нашего рендера нет — любой баннер нативный).

## Разбор

- **Маркер пишется ДО формулы, не после**: крах посреди blanket'а оставляет
  репею priors — иначе снапшот догонял бы состояние, где «прошлое» уже
  затёрто нашими нулями.
- **Сбой Apply не хоронит состояние**: откат идёт по свежему снимку
  идемпотентно (DeleteValue тих на отсутствующих); неудачный откат маркер
  НЕ стирает — следующий старт дочинит. Неудача репейра маркера, наоборот,
  валит Apply целиком: чинить поверх непочиненного нельзя.
- **BlanketSender не бросает никогда** (хендлер в пуле — необработанное
  исключение уронило бы процесс): сбой — строка трейса; глобальный тумблер
  и так душит обычные тосты, дыра — только reminder-сценарий этого
  отправителя до успешного повтора.
- **Возврат — в OnClosed после фида, а не в App.OnExit**: SuppressMode=
  OnMainWindowClose, жизнь окна = жизнь процесса — точка одна; Restore
  последним, чтобы фид молчал раньше, чем оживут баннеры.
- Грабля переустановки: `Add-AppxPackage` на ту же версию с другим
  содержимым — `0x80073CFB`; лечит Remove+Add (не ForceUpdateFromAnyVersion).
- Проверки реестра из баша: `$env:USERPROFILE`/`$k` съедаются двойными
  кавычками — одинарные снаружи или скрипт-файл (`spikes/tools/check-e1-state.ps1`).
- «settings.json мягче rules.json» — осознанно: правила — данные юзера
  (битый файл = дефолт опасен), настройки — один bool без накопленной ценности.

**Маршрут чтения**: `Core/Suppression/NativeBannerSuppressor.cs` (формула,
маркер, лок) → `Core/Suppression/INotificationSettingsRegistry.cs` (шов)
→ `Core/Settings/AppSettingsStore.cs` → `MainWindow.xaml.cs` (StartSuppression,
BlanketSender в Added, Restore в OnClosed) → `spikes/tools/check-e1-state.ps1`.

**Как проверить руками**: README «Подавление» (запуск → панели строки → тост
без баннера → диспетчером убить → маркер в `~\.rnotify\` → запуск (строка
ремонта) → закрыть → тост с баннером).

**Отложено сознательно**: uninstall-дыра (маркер остаётся при удалении
приложения — README-заметка; лечится ручной чисткой реестра или будущим
uninstall-расширением MSIX); изменение настроек без перезапуска; сценарии
alarm/urgent/incomingCall в бою под per-app (ожидаемо душатся — канон §10);
DND-взаимодействие формулы (NOC_GLOBAL_DND не трогаем).
