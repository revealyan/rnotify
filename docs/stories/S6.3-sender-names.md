# S6.3 — имя и иконка отправителя в карточках (Э2-остаток/Э4)

Статус: **done** (14.09 — «Claude Code (rhub)» с иконкой, «powershell» без
SID-пути; живой прогон владельцем).

## Что/зачем

Карточка показывала хвост AUMID (`powershell.exe`, `rhub`) — нечеловечно.
AppInfo листенера даёт ТОЛЬКО AUMID (канон §10c), DisplayName резолвится на
нашей стороне. Живой реестр машины подсказал цепочку: HKCU
`Software\Classes\AppUserModelId\<AUMID>` хранит DisplayName/IconUri Win32-
отправителей (rhub: «Claude Code (rhub)» + png; Spotify, ASUS…), для packaged
работает PackageManager (FamilyName!префикс → DisplayName + Logo).

## Результат

- `src/rnotify/Render/SenderResolver.cs`:
  - `Resolve(aumid)` → `SenderInfo(Name, Icon)`, кэш по AUMID под локом;
    резолв вне лока (реестр/PackageManager — десятки мс), события фида — пул.
  - Цепочка: реестр (HKCU→HKLM) → PackageManager (снимок пакетов один на
    процесс, `FindPackagesForUser("")`; ошибка снимка гасит ветку и хранится
    в `PackagesSnapshotError`) → фолбэк `NameFromAumid` (хвост без `.exe`,
    без фейковой капитализации: «rhub» остаётся rhub).
  - Иконка: IconUri/Logo — путь или file:///; `BitmapImage` OnLoad + Freeze
    (создание в пуле — чтение на Dispatcher); нет файла → null → карточка
    показывает 🔔-плейсхолдер.
- Карточка: конструктор принимает `SenderInfo`; бейдж 36×36 — иконка 24×24
  поверх плейсхолдера; имя в строке отправителя. `NameFromAumid` переехал
  из CardWindow в резолвер (VictimFocus матчит процессы им же).

## Живой прогон (пакет 0.1.0.0, глаза владельца)

- Тост из powershell (AUMID — полный путь с SID): карточка «powershell»,
  иконки нет (в AppUserModelId-реестре его нет — только фолбэк).
- rhub-карточки: «Claude Code (rhub)» + иконка (реестровая ветка).

## Разбор

- **Реестр AppUserModelId — рабочий источник имён Win32-тостов**: туда
  пишут отправители (rhub, Spotify); DisplayName+IconUri одним ключом.
  AUMID с бэкслэшами (полные пути) OpenSubKey читает как вложенность —
  прозрачно.
- PackageManager-снимок кэшируется на процесс: перечисление ~сотни мс,
  на каждый торт не дёргаем.
- `Package` живёт в `Windows.ApplicationModel`, а `PackageManager` — в
  `Windows.Management.Deployment` (алиас-using).

**Маршрут чтения**: `Render/SenderResolver.cs` → `Render/CardWindow.xaml`
(бейдж) → `MainWindow.OnNotificationAdded` (резолв в пуле).

**Отложено сознательно**: извлечение иконок из exe (powershell останется без
иконки; P/Invoke ExtractIconEx — если заболит); кэш на диск; локализация имён.
