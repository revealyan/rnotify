# S4.2 — рендер-карточки WPF в продукте (Э4): порт из спайка + вердикты правил

Статус: **done** (14.09 — карточки стека, TTL/sticky/цвет/клик/killNative из
`rules.json`, гашение по Removed; живой прогон владельцем; вотчер столов
удалён по факту канона — карточки видны на всех столах стилями окна).

## Что/зачем

Э4-продукт: механика карточки из спайка S4.1 (вердикт «WPF») переносится в
`src/rnotify` и соединяется с вердиктами Э3 — тост фида превращается в
карточку стека с TTL/акцентом/кликом из правил. Решения владельца на
план-гейте (13.09): **S1.2 (формула Э1 в продукте) — отдельной сторей после**
(нативные баннеры остаются включёнными — удобно сверять материал карточек с
родными); **click: focus — включить** (ALT-трюк из спайка); **overFullscreen —
отложить** (поле вердикта игнорируем, карточки всегда topmost).

Гипотезы стори (спайк-фёрст): механика спайка переносится в MSIX-продукт без
изменений (PMv2-манифест решает DPI); собственный снос нативной копии
(killNative) не должен гасить только что показанную карточку — фильтр
самосноса по intent-first-сетке Id.

## Результат

- `src/rnotify/Render/` (namespace `rnotify.Render`, UI-сборка — ядро не
  тронуто, arch-тесты целы):
  - `CardWindow` (XAML + code-behind): оверлей 372×124 DIP, WindowStyle=None /
    Topmost / ShowActivated=False / AllowsTransparency, WS_EX_NOACTIVATE |
    WS_EX_TOOLWINDOW в OnSourceInitialized; контент из записи, акцент-полоса
    группы (кривой hex → без полосы + строка трейса), TTL из вердикта
    (DispatcherTimer; null = sticky; OnClosed → Stop — таймер не должен
    пережить окно), вход slide+fade 250 мс, `Dismiss()` fade 167 мс со
    стражем; `FocusRequested` только при click=focus; `SenderFromAumid` —
    хвост AUMID без `.exe`.
  - `CardStack`: свежая снизу в зоне баннера, старые +140 DIP вверх
    (анимация `Window.Top` 167 мс CubicEase), лимит 3 — 4-я вытесняет
    старейшую; `Card.Closed` — единая точка пересборки; `CloseById` — тихий,
    если карточки нет (Removed бывает без карточки: mute/delete/backlog);
    `Trace`-событие — канал верификации в панель («показ/вытеснена/закрыта по
    Removed/фокус»). Контракт: все вызовы на Dispatcher (MainWindow
    маршалит из пула).
  - `VictimFocus`: AUMID → имя процесса → окно максимальной площади →
    IsIconic/SW_RESTORE + ALT-трюк + SetForegroundWindow; синхронно в клике.
- `src/rnotify/app.manifest` (PMv2, dpiAware true/PM) + подключение в csproj.
- Врезка `MainWindow`: стек создаётся до старта фида; show-вердикт открывает
  карточку той же посылкой BeginInvoke, что и строка «+ id» (FIFO: «+» всегда
  выше «−»); `RequiresNativeRemoval` → intent-first-снос из Центра
  (Id в сетке `_selfRemoved` ДО `RemoveNotification`, откат по исключению);
  чужой Removed → «− id» + гашение карточки. `App.xaml`:
  `ShutdownMode=OnMainWindowClose` — карточки не продлевают жизнь процессу.
- **Живой прогон (пакет 0.1.0.0, Win 26200, глаза владельца + «Скопировать
  всё»)**: стек и вытеснение («показ»/«вытеснена … лимит 3»), TTL 5 с и 3 м,
  sticky, акцент-полоса, клик focus поднял окно PowerShell жертвы (ALT-трюк,
  9243 px²), killNative снёс нативную копию из Центра, хот-релоад правил,
  backlog пропущен молча, живой трафик rhub — catch-all-карточки; снос из
  Центра руками → «− id» + карточка гаснет; карточка видна на всех
  виртуальных столах.

## Разбор (послесессионный тур)

**Карта изменений**:

- `src/rnotify/Render/` — CardWindow (XAML+cs), CardStack, CardTraceEventArgs,
  VictimFocus (~700 строк, коммит 1) + удаление DesktopSwitchWatcher
  (коммит 2).
- `src/rnotify/app.manifest`, csproj — PMv2.
- `src/rnotify/MainWindow.xaml.cs`, `App.xaml` — врезка и режим выхода.
- `spikes/tools/probe-desktop-switch.ps1` — пробник 0x0020 (артефакт факта).
- Тесты Core не тронуты — 30/30 зелёных.

**Решения и почему**:

- **Инверсия фильтра самосноса — баг, пойманный живым прогоном**. Первая
  редакция `selfRemoved = !_selfRemoved.Remove(e.Id)` инвертировала смысл:
  собственный killNative-снос проходил как чужой («− id» + карточка гасила
  себя), а юзерский снос из Центра молча фильтровался — карточки висели
  вечно. Владелец поймал оба симптома в одном дампе панели; фикс —
  `wasSelfRemoved = _selfRemoved.Remove(e.Id)` (Remove=true ⇔ Id был в сетке
  наших сносов). Урок: булевая семантика «Remove как try-consume» обязана
  читаться без отрицания.
- **Intent-first-сетка `_selfRemoved`**: Id помечается ДО `RemoveNotification`
  — собственный Removed-дифф прилетает из пула и может обогнать возврат
  вызова. Откат пометки по исключению — снос не удался, событие не придёт.
- **Столы: вотчер удалён, карточки видны на всех столах стилями окна.**
  Итог вечера бисекции: `EVENT_SYSTEM_DESKTOP_SWITCH` (0x0020) **не
  прилетает на 26200.9168 вообще** — ни ручные хоткеи, ни Task View, ни
  синтетические клавиши; слушатели любых сортов (unpackaged WPF-спайк,
  packaged MSIX-продукт, PowerShell-пробник; хук ставится, OnWinEvent не
  вызывается ни разу — журнал-заглушка). «Ездила» в спайке (С8 ✅ 13.09 и
  повторно 14.09 глазами владельца) объясняется не событием, а самим окном:
  неактивируемый topmost-оверлей (WS_EX_NOACTIVATE, ShowActivated=False)
  винда не привязывает к столу — карточка видна везде, как панель задач.
  Решение владельца: вотчер/дебаунс/пересоздание — выкинуть; факт —
  канон §9; если на будущих сборках omnipresence отвалится — новый спайк
  (пробник в `spikes/tools/` уже готов).
- **Фокус жертвы — эвристика с известной шершавостью**: окно поднимается
  (restore + ALT-трюк), но передний план Windows отдаёт не всегда
  (foreground-lock; живой прогон: поднялось «в бэкграунде»). Доводка
  (повтор/AttachThreadInput) — остаток Э4; отказ эвристики не меняет
  поведение (карточка закрывается).
- **Entry без Verdict**: после удаления пересоздания запись стека хранит
  только Card/Record/FocusHandler — вердикт замыкать незачем.
- **ShutdownMode=OnMainWindowClose**: жизнь приложения = жизнь окна-панели;
  детерминированный выход при открытых карточках (проверен живьём).

**Грабли пути**:

- PowerShell 5.1 `Add-Type` не знает discard `_ =` и `Environment.TickCount64`
  (компилирует под .NET Framework) — пробник переписан под старый C#.
- `MsgWaitForMultipleObjects` + `GetMessage` в одном потоке — дедлок
  (QS_SENDMESSAGE будит ожидание, GetMessage после него блокируется навечно):
  насос пробника — фоновый поток с чистым GetMessage-циклом, как в вотчере.
- Синтетическая стрелка требует сканкод + KEYEVENTF_EXTENDEDKEY (без 0xE0
  скан 0x4D читается как numpad-6, хоткей не срабатывает); при этом синтетика
  и с extended не рождает 0x0020 — переключение есть, события нет (и это не
  индикатор: ручные пути тоже молчали).
- RID win-x64 в csproj раскладывает свежие сборки в `bin/**/win-x64/` —
  бинарник в корне `bin/Debug/net10.../` оказался протухшим (запуск старья
  дал бессмысленный прогон; проверяй timestamp).
- Анализаторы: MA0046 (события — EventHandler/`<T>EventArgs`-типы), MA0134
  (discard на fire-and-forget BeginInvoke), MA0048 (CardTraceEventArgs — свой
  файл), IDE1006 (`_camelCase` приватных), CS0262 (XAML-паршл — public).
- MSIX «не при чём»: packaged и unpackaged молчали одинаково — упаковка не
  фильтрует WinEvent-хуки (в пределах этого вечера).

**Маршрут чтения**: `Render/CardWindow.xaml.cs` (окно, стили, TTL) →
`Render/CardStack.cs` (стек-3, трейс) → `Render/VictimFocus.cs` (клик-focus)
→ `MainWindow.xaml.cs` (врезка: вердикт → карточка, самоснос) →
`spikes/tools/probe-desktop-switch.ps1` (пробник 0x0020).

**Как проверить руками**: собрать пакет (README «Сборка») → `Add-AppxPackage` →
запуск → `send-test-toast.ps1 -Title kill` → карточка 3 м + нативная копия
снесена из Центра, «− id» своего сноса в панели НЕТ, карточка жива → снести
её руками из Центра → «− id» + карточка гаснет → Win+Ctrl+→: карточка видна
на другом столе → закрыть окно-панель при открытых карточках → процесс ушёл
(`Get-Process rnotify` пуст).

**Отложено сознательно**: S1.2 — применение формулы Э1 (нативные баннеры
включены); overFullscreen (topmost всегда); мультимонитор; подгонка материала
под нативный тост; резолв AUMID → имя/иконка; редактор правил; floor на диске
(анти-дубли между запусками); доводка foreground у фокуса жертвы; поведение
карточек на Future builds, где omnipresence-стили могут отвалиться.
