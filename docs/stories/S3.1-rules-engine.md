# S3.1 — политика правил (Э3): движок матчинга, конфиг v2, хот-релоад

Статус: **done** (13.09 — движок и врезка в окне; живой прогон подтвердил
`RemoveNotification` из packaged и watcher на реальном профиле; рендера нет —
вердикты пока только строками панели).

## Что/зачем

Ядро Э3: `rules.json` → компиляция в immutable-движок → вердикт на каждое
уведомление фида. Решения владельца на план-гейте: **движок + живая врезка в
окно** (вердикты в панели; delete/killNative применяются живьём — заодно первая
проверка `RemoveNotification` из packaged), **хот-релоад сейчас**
(FileSystemWatcher + дебаунс 300 мс), **конфиг
`%USERPROFILE%\.rnotify\rules.json`** (unvirtualizedResources уже в манифесте),
**схема полная v2** старого rnotif (ttl/killNative/click/цвет едут в вердикте,
применяются с рендером Э4). Опыт старого rnotif — гипотеза; его баги не
скопированы: regex без таймаута, молчаливый fallback на дефолт при опечатке,
case-sensitive ttl, non-nullable bool в DTO, watcher без Error-обработки.
App-матчер — только по AUMID (DisplayName в контракте 22621 нет).

Гипотезы стори (спайк-фёрст): `RemoveNotification(id)` из packaged работает без
дополнительных capability; `FileSystemWatcher` видит правки файла в реальном
профиле из-под пакета. Живой прогон = эксперимент, факты — канон §10c.

## Разбор (послесессионный тур)

**Карта изменений**:

- `src/rnotify.Core/Rules/` — 14 файлов (~450): ядро Э3.
- `src/rnotify.Core/Listener/INotificationSource.cs` (+член),
  `UserNotificationSource.cs` (+реализация) — шов сноса.
- `tests/rnotify.Core.Tests/` — 4 тест-класса + `TempRulesDir` (16 тестов).
- `src/rnotify/MainWindow.xaml.cs` — врезка правил (~60 строк поверх Э2).
- `docs/stories/ROADMAP.md`, `README.md` — статус и раздел «Правила».

**Решения и почему**:

- **CatchAll = show 5 с** (ноль правил или нет матча): диспетчер обязан
  показать непокрытое — молчаливое проглатывание недопустимо по конституции.
- **Выбраковка с отчётом, не молчаливый fallback**: кривое правило уходит в
  `DiscardedRule` с причиной, соседние живут; грабля старого rnotif — опечатка
  в action молча превращала правило в дефолт. Панель показывает
  «выброшено N: имя (причина)».
- **Битый конфиг = прежний движок**: «последний рабочий» — осознанный выбор;
  перезагрузка не может ухудшить поведение. Ошибка — событием и строкой, файл
  не трогаем.
- **Regex-таймаут 100 мс, таймаут ≈ не совпало** (правило живо): катострофический
  бэктрекинг пользовательского паттерна не должен вешать дифф-цикл фида.
  Проверен тестом `(a+)+$` с таймаутом 1 мс.
- **Вердикт один раз на пуле**: движок immutable → Decide потокобезопасен по
  построению; UI получает готовую строку через BeginInvoke, поставленный ДО
  вызова Remove (FIFO Dispatcher: «+» всегда выше «−» своего сноса).
- **Снос из Центра ≠ «показать и прихлопнуть»** (конституция п.2): это
  управление хранилищем по правилу владельца; побочный Removed-дифф того же id
  — ожидаем и видим в панели. Происхождение Removed («мы» vs «юзер») отличать
  в Э4.
- **Watcher без Deleted**: atomic-save редакторов — это tmp+rename = Created/
  Renamed; Deleted означал бы «файл исчез совсем» — на этом событии
  перезагружать нечего, ошибка чтения сама скажет всё.
- **Фикс живого прогона — кириллица дефолт-конфига**: дефолтный encoder
  `System.Text.Json` гонит весь не-ASCII в `\u-эскейпы`; файл правится руками →
  `JavaScriptEncoder.UnsafeRelaxedJsonEscaping` только на запись + страж-тест.
- **Грабли анализаторов**: MA0016 (`IList` в DTO вместо `List`), RCS1075
  (пустой catch → `Debug.WriteLine`), CS8604 (`[NotNullWhen]` не работает на
  не-bool возврате — `!` с комментарием), CS1525 (static-лямбда после `??`
  требует скобок). NRE-баг компиляции: общий `out error` на трёх матчерах
  затирался успешным вызовом — раздельные `appError/titleError/bodyError`.

**Маршрут чтения**: `RulesEngine.cs` (компиляция/Decide/ttl) → `RulesStore.cs`
(конфиг, атомарность) → `RulesReloader.cs` + `RulesMonitor.cs` (хот-релоад) →
`MainWindow.xaml.cs` (врезка) → `RulesEngineTests.cs`.

**Как проверить руками**: собрать пакет (README «Сборка») → `Add-AppxPackage` →
запуск: строка «Правила = …: 3 правил», файл `~\.rnotify\rules.json` создан →
`send-test-toast.ps1 -Title mute/delete/kill` → вердикты в панели, delete/kill
исчезают из Центра → правка json в блокноте → «перезагружено» без рестарта →
срезать скобку → «ошибка … прежний конфиг» → «Скопировать всё» → вставка.

**Отложено сознательно**: редактор конфига (Э4, после выбора UI-стека);
резолв имени/иконки отправителя; применение ttl/цвета/click/overFullscreen
(рендер Э4); origin у Removed-событий; массовые операции/импорт конфигов;
per-rule приоритеты вне порядка файла.
