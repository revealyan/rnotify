# S5.3a — релизный пайплайн: тег → MSIX → GitHub Release

Статус: **done** (13.09 — пайплайн собран и слит; живой тег `v0.1.0` и публикация
Release — стоп-точка, только по команде владельца).

## Что/зачем

Закрывает долг S5.1 («версионирование манифеста из CI, релизный MSIX — S5.3»):
тег `v*` → Actions собирает Release-MSIX с версией из тега → вложение в GitHub
Release. Решения владельца на план-гейте: **только пайплайн** (стор-сабмит
отложен до появления функциональности, Э2+) и **unsigned-артефакт** (Certum не
покупаем, пока стор-вопрос не решён). Identity из `docs/store-identity.md`
пайплайн не трогает.

## Результат

`.github/workflows/release.yml`: тег `v*` → checkout → setup-dotnet 10 →
подстановка версии из тега в манифест (`v0.1.2` → `0.1.2.0`, в checkout-копии)
→ restore/build/test Release → `softprops/action-gh-release@v2` с MSIX и
generated notes. Подписи нет: pfx живёт только локально (рельса S5.1 — условие
`Exists(pfx)` в csproj), CI собирает unsigned без секретов.

## Разбор (послесессионный тур)

**Карта изменений**:

- `.github/workflows/release.yml` (новый, ~48) — весь пайплайн; shell: pwsh.
- `spikes/tools/test-version-subst.ps1` (новый) — рельса-тест подстановки
  версии: копия манифеста, сломанная/рабочая формы, exit 1 при промахе.
- `docs/stories/ROADMAP.md` — S5.3 пере-размечен: S5.3a ✅ / S5.3b ⏳.
- `README.md` — раздел «Релизы» (тег → Release; локальная подпись unsigned).

**Решения и почему**:

- **Версия — из тега, в репе дефолтная** `0.1.0.0`: теги — единственный
  источник релизных версий; манифест правится в checkout-копии CI, репо не
  пачкается коммитами «bump version».
- **Главная грабля сессии — `$10`-группа**: replacement
  `` "`$1$version.0`$2" `` при версии с цифры (`0.9.3`) интерполируется в
  строку `$10.9.3.0$2`; .NET-regex парсит `$10` как ссылку на группу 10 —
  несуществующую → пусто. В .NET-replacement группа попадает в вывод ТОЛЬКО
  явной ссылкой, значит группа 1 не упомянута → весь матч
  `<Identity … Version="0.1.0.0"` заменяется на огрызок `.9.3.0"` — элемент
  Identity исчезает из манифеста целиком. CI умер бы на упаковке с невнятной
  ошибкой. Лечение — фигурные скобки `` "`${1}$version.0`${2}" ``; поймано
  локальной рельсой ДО пуша (воспроизводится: `test-version-subst.ps1`).
- **pwsh в CI vs PS 5.1 локально**: CI-шаг на pwsh 7 (чтение/запись UTF-8
  без BOM по умолчанию), локальная рельса — PS 5.1 (BOM-файл, явный
  `-Encoding UTF8`, `[Console]::OutputEncoding` для кириллицы в пайпе — §10a).
- **unsigned осознанно**: пакет ставится только после локальной подписи
  дев-сертом (`certs/rnotify-dev.pfx`, subject = Publisher манифеста — identity
  совпадает); артефакт пригоден для своих машин и будущей подписи S5.3b.
- **Живой тег — стоп-точка**: пуш `v0.1.0` создаёт публичный Release (внешний
  эффект) — только по явной команде владельца.

**Маршрут чтения**: `release.yml` (комментарии внутри) →
`spikes/tools/test-version-subst.ps1` (доказательство грабли) → README
«Релизы».

**Как проверить руками**: `powershell -File spikes/tools/test-version-subst.ps1`
→ `рабочая … Version="0.9.3.0"`, `OK`. Живой прогон: тег `v0.1.0` на main →
в Actions job release зелёный → Release содержит `rnotify_0.1.0.0_x64.msix`.

**Отложено сознательно**: релизная подпись и стор-сабмит (S5.3b: Partner
Center, обоснование restricted declarations — канон §10c, риск РФ-аккаунта,
план Б Certum + winget-community); осмысленные release notes (пока
generated); публикация тега без функциональности (Э2 даст `v0.2.x`).
