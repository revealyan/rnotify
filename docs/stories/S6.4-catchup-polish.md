# S6.4 — догоняющие после краха + полировка (floor, foreground, материал)

Статус: **done** (15.09 — floor-антидубли с правилом владельца «показать то,
что не увидел», липкий поток с плашкой «Пропустить всё», материал карточки
по замеру нативного баннера; живые прогоны владельцем).

## Что/зачем

Три остатка одной волной. (1) **Floor-анти-дубли**: backlog при старте молча
пропускался — то, что пришло, пока формула висела погашенной (крах), юзер не
видел вообще. Правило владельца: «пользователь должен увидеть то, что не
увидел» — увидел ли, выводится из состояния формулы: чистый выход возвращал
баннеры (видел нативно), крах оставлял погашенными (не видел ничего).
(2) **Foreground-доводка click:focus** — окно жертвы поднималось «в
бэкграунде» (foreground-lock). (3) **Материал карточки** — «цвет другой
немножко» (вердикт S4.1).

Догоняющие по ходу прогонов получили продукт-форму (просьбы владельца):
поток не каскадом, липкие «закрываешь ты», плашка «скипнуть всё как в телеге».

## Результат

- `rnotify.Core.Listener.NotificationFloor` — seen.json: пары (Id,
  CreationTime) — Id хранилища переиспользуется после сноса, время отличает
  рециркуляции; чистка 7 дней / топ-1000; атомарная запись; битый файл =
  пустой (лучше дубль, чем потеря).
- `ListenerStartResult.Baseline` — записи базлайна наружу (было только число).
- `NativeBannerSuppressor.TryRepairMarker()` — публичный ремонт маркера БЕЗ
  применения (consent-ветка тоже обязана вернуть юзеру баннеры) +
  `RepairedFromCrash` — признак «формула висела мёртвой» для догонялки.
- `MainWindow.CatchUpMissed`: не увидел = нет во floor И RepairedFromCrash;
  увидел нативно/карточкой → молча в floor. Лимит `catchUpLimit` (settings,
  0 = выкл; хвост за лимитом молча), свежайшие вперёд.
- Режимы потока `catchUpSticky` (дефолт true): карточки без TTL, стек
  заполняется сразу, подача по `CardStack.SlotFreed` (закрыл — пришла
  следующая); false — пейсинг 1.5с, TTL вердикта сам двигает.
- `Render/CatchUpBanner` — неактивируемая плашка над стеком: счётчик
  остатка + «Пропустить догоняющие» (гасит очередь И экран: CardStack.
  CloseCatchUp по помеченным Entry.IsCatchUp); ездит со стеком
  (MoveAbove(VisibleCount)); живёт до последней догоняющей.
- `VictimFocus`: AttachThreadInput-танец (приаттач к потоку переднего окна →
  SetForegroundWindow+BringWindowToTop → детач) поверх ALT-трюка;
  GetCurrentThreadId — kernel32 (грабля канона §10d).
- Материал: фон карточки **#28282B** (альфа F2) — замер живого баннера
  (`spikes/tools/measure-banner-color.ps1`: фон зоны #0C0E0F, bbox 550×142
  физ., замес при альфе 1.0/0.9).

- Краш → тост в мёртвый интервал → перезапуск: ремонт маркера строкой,

- Поток: 7 в очередь — строки «Догон» по каждой, живой rhup вразнобой, стек-3.
- Липкие: 3 на экране не исчезают, закрыл — сместились, новая пришла;

## Разбор

- **Гонка BeginInvoke в подаче**: карточка ставится в стек через async-
  посылку — чтение VisibleCount сразу после неё даёт СТАРОЕ значение
  (лог-диагностика плашки: moveAbove(0) через 0.5с после старта = преждевременный
  «финиш»). Лечение: показанное считать локально, жизненный цикл плашки
  решают закрытия/скип, а не подача.
- **Семантика скипа**: «скипнуть всё» ≠ «слить очередь» — очередь в липком
  режиме выкачивается мгновенно, а карточки-то висят; ранний выход по
  «очередь пуста» делал кнопку тыквенной. Плашка живёт, пока очередь ИЛИ
  экранная догоняющая; скип гасит оба.
- Холодный старт floor: первый запуск с пустым seen.json показал весь
  backlog разом (24 карточки каскадом — «миллион уведомлений» владельца) —
  после кэпа/потока шум у форматированный; повторится только после 7+ дней
  простоя с крахом.
- Live-карточка вытесняет липкую догоняющую (стек-3): непрочитанная теряется
  (в floor помечена) — редкий конфликт, принял.
