# S4.1 — спайк Э4: сравнение UI-стеков рендера карточек (WPF vs WinUI 3)

Дата: 13.09.2026 · ветка `s4.1-render-spike` · протокол: `spikes/SPIKE-S4.1.md`

## Что и зачем

Конституция п.5: «UI-стек — по итогам спайка». Сравнили WPF и WinUI 3
(Islands отброшены по докам — «tested for C++ only») на матрице
«карточка+столы» (С1–С8), один монитор 2880×1800 @150%, живой трафик rhub.
Тайбрейкер по план-гейту — визуальный паритет с нативным тостом (глаза
владельца).

## Результат

**Выбран WPF.** Матрица:

| Сценарий | WPF | WinUI 3 |
|---|---|---|
| С1 позиция/отрисовка | ✅ | ✅ |
| С2 не-активация (фокус) | ✅ | ✅ |
| С3 топмост | ✅ поверх borderless-фуллскрин-игры | ❌ **WS_EX_TOPMOST недостижим** (4 пути) |
| С4 чёткость 150% | ✅ | ✅ |
| С5 материал (тайбрейкер) | ❌ имитация | ✅ системный акрил |
| С6 анимация входа/выхода | ✅ | ~ (процесс-уровень) |
| С7 клики | ✅ | ⚠️ ✕ мёртв, тело ✅, белая рамка кнопки |
| С8 виртуальные столы | ✅ | ✅ |

Вердикт владельца: тайбрейкер за WinUI («вин ui ближе»), но С3 —
функциональный блокер для диспетчера (карточка обязана жить поверх
развёрнутых окон, как нативные баннеры над borderless-играми), С5 —
подгоняемая косметика → **WPF**, WinUI переоткрыть при находке пути topmost.

## Разбор

- **Раунд 0 (эталон)**: нативный баннер 372×110 DIP, поля ~12 DIP; карточки
  подняты до 372. Открыт гейт §10a: под локскрином пиксельные прогоны
  невалидны (окна за локом, дифы = 0 без диагноза).
- **Детектив невидимости WinUI** (полдня): симптом «окно есть, пикселей
  нет» → перебраны MoveAndResize до/после Show, SetWindowPos, NOACTIVATE,
  Entrance-анимация, акрил, презентер, DWM-cloak → метод-ловушка: пробы
  без DPI-aware врут координатами ÷1.5 (чуть не «скомпенсировал» окно за
  экран — DWM-bounds 3456,2286 при 2880×1800) → истина через
  WindowFromPoint/exstyle: **карточка была исправна, но не-topmost и
  пряталась за фуллскрин-игрой владельца**. WPF (Topmost) на той же сцене
  был виден. Урок в §10a: все пробы окон — DPI-aware, зонд невидимости —
  PrintWindow + WindowFromPoint + DWM-bounds.
- **Тайбрейкер-сцена**: «стопка» из sticky-карточек (--offset 290/140 DIP,
  флаг добавлен обоим хостам) + бурст нативных баннеров (окно эталона ~5 с
  на баннер — одиночного тоста владельцу не хватило).
- Багфикс обоих хостов: `GetCurrentThreadId` — kernel32 (EntryPointNotFound
  валил джойстик).
- Спайки вне rnotify.slnx; прод-код не тронут.

## Маршрут

1. Каркас: два спайк-хоста (карточка+джойстик+столы+ALT-трюк) + 2
   PS-инструмента (native-banner-zone, render-card-check) — `b0dd991`.
2. Раунд 0 + гейт локскрина + фикс kernel32 — `cd4ff59`.
3. Раунды 1–2 (авто): WPF С1/С2/С3; WinUI topmost-блокер, DPI-ловушка —
   `4a51e03`.
4. Глазная часть: тайбрейкер, С4/С7/С8, `--offset` — `5dc4e91`.
5. Вердикт + канон §10d + эта сторя — финальный коммит.

## Проверка руками

Автогоново: `spikes/tools/render-card-check.ps1 -ExePath <exe> -Ttl 6`
(зона, Noise/D300/D1500/AfterExit, foreground-чек); эталон —
`native-banner-zone.ps1`. Глазное — сцена «стопка» + бурст тостов.

## Отложено (в S4.2 — рендер-механика продукта)

- Подгонка материала WPF к нативному (цвет/прозрачность; референсы — WPF
  UI, MicaWPF); анимации по Fluent-кривым тонко.
- Стек-3 колонок, мультимонитор (SetWindowPos-хак WinUI — не нужен, WPF
  DIP-нативен), темы.
- Переоткрытие WinUI при находке пути topmost (факт-блокер зафиксирован).
- Резолв AUMID → имя/иконка отправителя; click:focus-эвристика; интеграция
  в rnotify (джойстик остаётся диагностическим окном).

## Горизонт

Э4 строится на WPF: `src/rnotify/` получает рендер-механику из спайка
(оверлей-окно, зона 372 DIP, столы-пересоздание, ALT-трюк), правило
`ttl`/цвет/клик из движка S3.1 применяется к карточке.
