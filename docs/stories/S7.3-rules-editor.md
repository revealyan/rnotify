# S7.3 — редактор правил (Э4-остаток, последний большой кусок UI)

Статус: **done** (15.09 — группы/правила, сохранение через RulesStore с
хот-релоадом, Ctrl+Shift+N настройкой; живой прогон владельцем: правка цвета
доехала до карточки акцент-полосой).

## Что/зачем

rules.json правился руками (S3.1); канон §9 планировал редактор. Принцип
владельца «всё в настройки»: хоткей `rulesHotkey` (дефолт Ctrl+Shift+N) +
пункт меню трея «Правила…». Редактор не дублирует валидацию — движок
(доктрина S3.1: кривое значение = выбраковка правила со строкой в панели,
не блок редактора).

## Результат

- `src/rnotify/Rules/RulesWindow.xaml(.cs)`: одна на приложение. Слева
  группы — вкл/имя/цвет с живым превью акцента (GroupItem c INPC только для
  превью; конфиги — POCO). Справа правила выбранной группы карточками:
  name/app/title/body, match (regex/contains/exact + дефолт), action
  (show/mute/delete), ttl, click (close/focus), killNative, overFullscreen.
  Структурные операции (+/− группа, + правило; − правило снимает последнюю —
  v1 без выбора строки) пересобирают панель. Сохранение — RulesStore.Save
  (атомарно) → хот-релоад → строка «перезагружено» в панели. Esc/Отмена —
  без сохранения.
- `TrayIcon`: второй хоткей-слот (id 2) + пункт меню; Unregister обоих.
- `MainWindow`: `_rulesStore` поле; OpenRules; строка состояния хоткея.

## Живой прогон (пакет 0.1.0.0, глаза владельца)

- Ctrl+Shift+N и меню трея открывают редактор (грабля прогона: владелец
  жал Win+Shift+N по привычке истории — «а епт, контр»).
- Правка цвета группы «Мусор» + Сохранить → тост по kill-правилу пришёл
  **с новой акцент-полоской** — правка доехала через хот-релоад до вердикта.

## Разбор

- **TextBox-поля без проводки записи** — грабля первой редакции, поймана
  ревью до живого прогона: хелпер создавал TextBox, но не подключал
  колбэк записи (правки name/app/title/body/ttl терялись бы молча).
- Пустое поле → null (json чище, дефолты движка работают), не пустая строка.
- Редактор правит СВОЙ снимок конфига (store.LoadOrDefault при открытии) —
  живой движок не мутируется, файл — единственная точка синхронизации.

**Маршрут чтения**: `Rules/RulesWindow.xaml.cs` (GroupItem, BuildRuleCard,
OnSave) → `TrayIcon.TryRegisterRulesHotkey` → `MainWindow.OpenRules`.

**Как проверить руками**: Ctrl+Shift+N → правка → Сохранить → строка
«перезагружено» в панели → тост по правилу.

**Отложено сознательно**: выбор/удаление конкретного правила (сейчас
последняя), перетаскивание порядка (порядок = приоритет матча!), живое
сохранение без кнопки, валидация regex в редакторе.
